# Working with AI agents

Redline is built so a coding agent can find a performance problem, fix it and prove the fix,
using recorded data instead of guesses. Everything here is read-only unless stated.

## Machine-readable docs

| File | What it is |
|---|---|
| [`/llms.txt`](llms.txt) | Index of every page with a one-line summary ([llmstxt.org](https://llmstxt.org) format) |
| [`/llms-full.txt`](llms-full.txt) | All pages in one file, for loading into a context window |
| [`/reference/settings.schema.json`](reference/settings.schema.json) | Every setting with its type and default (JSON Schema) |
| [`/reference/cli.json`](reference/cli.json) | Every command and flag |

They are generated by `scripts/build_llms.py`; CI fails when they are stale.

## Give your agent the instructions

```bash
redline agent-skill --write ~/.claude/skills        # a Claude skill: .../redline/SKILL.md
redline agent-skill --format agents --write .       # AGENTS.redline.md to merge into AGENTS.md
```

The text covers how to find problems, fix them and verify, and the rules below.

## MCP server

```bash
redline mcp --store .redline/redline.db [--audit .redline/agent-audit.jsonl]
```

It speaks the Model Context Protocol over stdio (line-delimited JSON-RPC) and opens the store
read-only. Example client entry:

```json
{ "mcpServers": { "redline": { "command": "redline", "args": ["mcp", "--store", ".redline/redline.db"] } } }
```

| Tool | Returns |
|---|---|
| `list_issues` | Findings ranked by sampled impact, each with `why`, callsite and suggestion |
| `explain_issue` | One finding in full |
| `get_trace` | A bounded request summary: timings, issues, slowest spans (no bodies or logs) |
| `instrumentation_report` | What redline cannot see: inactive integrations, truncated traces, drops |
| `verify_fix` | gone / still_present / inconclusive from a saved compare report |
| `llm_summary` | Sampled LLM-call tokens and counts per route and model |

Bad input produces an error result the model can read; the server keeps running. Output is
bounded in size. With `--audit`, each call is appended as a JSONL record containing the tool
name, argument *names* and timing, never argument values. The file is created with mode 0600.

## The fix loop

```bash
redline fix-prompt ISSUE_ID --store .redline/redline.db > brief.md   # evidence + constraints
redline check record check.toml                                      # baseline, before editing
# ...the agent edits the code...
redline check compare check.toml --json report.json
redline check verify report.json --kind n_plus_one                   # exit 0 only when gone
```

`verify` answers `gone`, `still_present` or `inconclusive`. A finding is only `gone` when it
was in the baseline, is absent now, responses are equal, and the run had enough samples with
complete server metrics. If it says `inconclusive`, collect more samples; do not declare
success. See [Refactor check](refactor-check.md#verify-a-fix).

## Reviewing agent-written code in CI

```yaml
- run: redline check compare check.toml --json report.json --fail-on slower,changed,broken,budget
- run: redline check findings report.json --new-only --json > findings.json   # exit 1 if any
```

`findings` lists issues that are new relative to the baseline and includes a fix brief for
each, which an agent step can consume. Pair it with the pytest markers
(`@pytest.mark.redline(max_queries=…, no_n_plus_one=True)`) and the `redline check ratchet`
query-count ratchet so a change cannot quietly add queries.

## AI-assisted diagnosis

```bash
redline diagnose ISSUE_ID --store .redline/redline.db          # preview only, nothing is sent
redline diagnose ISSUE_ID --store .redline/redline.db --send   # opted in: really sends
```

Off by default. The default run prints the exact request (destination, model and body) and
exits. Sending needs three things together: `--send`, `ai_diagnosis = true` in the settings,
and the key in the `REDLINE_AI_API_KEY` environment variable. The destination host is fixed
for the provider (`api.anthropic.com`); it cannot be redirected. The body is an allowlist of
finding fields (kind, title, evidence, SQL *shape* with literals replaced, file, line,
function and one line of source) passed through the redactor. Request and response bodies,
logs and LLM prompt text are never part of it. Errors report the HTTP status only, never the
key or the provider's response body. Agents must not enable this themselves.

## Rules for agents

- Never capture, log or paste prompt or completion text, tokens, passwords or request bodies.
- Do not delete traces or run EXPLAIN ANALYZE against a production store.
- Do not weaken a test, threshold or budget to make a finding disappear.
- Do not push, tag or publish without the owner's approval.
- Do not enable `ai_diagnosis` or set `REDLINE_AI_API_KEY`; only the owner opts in.

## Safe deployment recipe

Run the app with `read_only = true` and `explain_analyze = false`, point `redline mcp` at a
*copy* or read-only mount of the store, and keep `--audit` on. The MCP process cannot write to
the store at all.
